# One completion authority — integration handoff

The QueryClient-scoped `OperationTracker` (shell-owned one WebSocket) is the sole terminal matcher. The old `correlateOperation` API is compatibility-only and immediately rejects with an attached rejection handler; `resolveOperationEnvelope` no longer processes frames. `trackAccepted` and `submitOperation` preserve 202 shape and `sendCommand` key behavior without automatically arming any promise; `followOperation` displays acceptance only, never generic corr success/timeouts. Unknown replay kind does not imply its original verb. All existing socket subscription/status/gap dispatch remains.

`switcherOperationEvidence` validates switcher.operation only on topic switcher, envelope id matching data.me, envelope corr matching data.operation_id, finite tick and boolean completed. It returns applied for completed=true, failed with optional engine error for completed=false. Tracker extension (separate owner commit 94379ac8) imports this pure predicate and requires {topic:'switcher',resource:'me1',event:'switcher.operation',terminal:{kind:'switcher-operation',me:'me1'}} and actual accepted kind (select_program/select_preview/cut/auto). No matching media loading, wrong M/E/topic/corr, progress, unsupported command, or replay can assert success.

SwitcherPage submits through useSubmitTrackedOperation, observes useOperationFeedback's authoritative phases, and keeps controls disabled for accepted and unknown, permitting another only after validated applied/failed. A separate `switcher` listener is preserved for state invalidation and displays a validated failure error only; it cannot settle a phase. Limitation: if a failed switcher event arrives before POST resolves, page-local display-only error may miss its text, falling back to translated `Switcher operation rejected`; tracker correctly marks failed. Captain can later put reason into tracker cached evidence/record if needed; no second matcher. No invented status endpoint, backend modifications, generated runtime or locales changes. New Lingui expressions reuse existing catalog strings; captain owns extraction.
