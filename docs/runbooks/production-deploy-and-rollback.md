# mda001 production engine and UI: deploy and rollback

This is the deployment procedure for `conspect.service` and its separate management UI on `mda001.public-servers.sy4.aperim.net`. The current procedure stops the socket for a controlled, brief outage to prevent automatic reactivation during the binary/configuration transaction. This document does **not** authorize deletion of old build trees, state, UI directories, credentials, or rollback binaries.

## Build from an exact main commit (off the live service path)

1. Coordinate a maintenance window. Record `systemctl show conspect.service -p MainPID -p ActiveEnterTimestamp`, `sha256sum /home/operations/conspect/target/release/multiview`, `df -h /`, and two authenticated `/api/v1/metrics/program` snapshots. Refuse a deployment if the baseline has rising missed ticks or if free space cannot hold a new build and rollback copies.
2. On the build host, `git fetch origin main`; set `SHA=<full chosen main commit>` and verify `git merge-base --is-ancestor "$SHA" origin/main`. Create an isolated checkout using `git worktree add --detach /home/operations/build-$SHA "$SHA"`; in that checkout, require `test "$(git rev-parse HEAD)" = "$SHA"` and empty `git status --porcelain`. Record the full SHA, `rustc --version`, `cargo --version`, exact feature flags, and build dependency versions. Never build from `/home/operations/conspect` or alter the active target in place.
3. Provision the native GPU/FFmpeg/SRT dependencies documented by the selected commit. Use an isolated target directory **inside the isolated checkout** and reproduce the measured production features (`default` remains enabled because `--no-default-features` is absent): `cargo build --locked --release -p multiview-cli --features 'acme,catalogue,catalogue-ffmpeg,cuda,devices-net,discovery,ffmpeg,gpu,heartbeat,mesh-mdns,moq-output,ntp,nvidia,overlay,rist,software,sqlite,srt-libsrt,tls,web,webrtc,webrtc-native,youtube'`. Check the binary path (`target/release/multiview`) and capture its SHA-256 and build log. If the selected commit changes feature names, resolve and record that explicitly; never silently omit a feature. Build the UI from the same clean SHA with `npm --prefix web ci && npm --prefix web run build`; confirm the output directory from `web/vite.config.*` / package scripts before copying. Do not compile during a production health incident.
4. Stage the built executable at `/home/operations/releases/$SHA/multiview` and UI at `/var/www/conspect-ui/$SHA/` using temporary names then rename **within the same filesystem**. Record SHA-256 for executable, `index.html`, and its referenced assets; ensure the service account can read them. Never replace an existing SHA directory with different bytes.

## Preflight, cutover, and health gate

1. On the authorized operator workstation, retrieve the admin secret from the named 1Password item into a private shell variable (for this harness: `secret="$(OP_SERVICE_ACCOUNT_TOKEN="$(bash /home/vscode/.dsh/skills/dsh-harness/scripts/dsh-env OP_SERVICE_ACCOUNT_TOKEN)" op read 'op://Servers/mda001.public-servers.sy4.aperim.net/conspect_control_token')"`); never print it, enable shell tracing, or put it in a command-line argument or history. Send the complete bearer `admin.${secret}` through a private stdin pipe to an SSH session that reads it without logging. The helper path is workstation-specific, **not a host path**. On the host, inspect `systemctl cat conspect.service conspect.socket`, `systemctl is-active conspect.socket`, current boot TOML and `.multiview/active.toml` `ui_dir`, the existing binary digest, and the current UI `index.html` digest. Save copies of both configuration files and the old executable at unique, timestamped names outside paths the service loads. Preserve mode, ownership, and symlinks. Do not expose `/etc/conspect/env` or the credential.
2. Run the candidate binary's `validate /home/operations/mv/conspect.toml` **as the service account**; require both boot config and accepted-state startup admission to say OK. Check the candidate's `--version`, executable shared libraries (`ldd`), UI files, TLS certificate path, socket activation, and disk headroom. Validation is side-effect-free. Refuse cutover if any check fails.
3. Enter a declared short outage: `sudo -n systemctl stop conspect.service conspect.socket`; confirm both are inactive before modifying anything (this prevents the watcher, restart policy, and socket-triggered activation from racing the update). Replace the service binary by staging a same-directory temporary file then atomic `mv` to `/home/operations/conspect/target/release/multiview`; this preserves the old image only if the unique rollback copy was verified first. Set `[control] ui_dir = "/var/www/conspect-ui/$SHA"` in **both** `/home/operations/mv/conspect.toml` and `/home/operations/mv/.multiview/active.toml` if accepted state persists the setting. Do not overwrite unrelated operator edits. Run candidate validation again; if it fails, restore the saved files and binary **before starting either unit**. Start `conspect.socket` then `conspect.service` with `sudo -n systemctl start conspect.socket conspect.service`. Confirm the new PID, executable checksum, and active state of both units. This is **not zero-downtime**; after a separate tested atomic deployment facility exists, a socket-preserving cutover can replace this conservative method.
4. Query `http://[::1]:8080/api/v1/health`, `/api/v1/metrics/program`, `/api/v1/metrics/frontdoor`, `/api/v1/sources/status`, and `/api/v1/outputs` with the bearer token. Require HTTP 200 and parse JSON. Compare tick totals over at least ten seconds; require growth and no new missed ticks/repeats. Check expected source phases, frontdoor errors/drops, and no new health warnings. Fetch public `/` and compare HTML/asset hashes with staged UI. Read the actual configured HLS output path from authenticated `/api/v1/outputs`; on this measured baseline, fetch public `/hls/restream/index.m3u8` twice and verify sequence/program date advance. Fetch its newest segment and use `ffprobe -show_packets` for monotonic video PTS/DTS and `ffprobe -show_streams`/`-show_frames` for color tags. Unknown tags are an existing baseline defect and must not be silently accepted as a new compliance proof; compare against the prior build and track remediation separately. Check journal errors and client playback before marking success.

## Rollback (keep the socket alive)

1. Before changing anything, identify the **actual immediately previous** binary backup and previous UI SHA from the cutover record. Check the executable hash and `--version`; run `previous-binary validate /home/operations/mv/conspect.toml` and ensure the previous UI `index.html` is readable. The known 2026-11-18 pair above is a *fallback*, not necessarily the immediately previous release after subsequent deploys.
2. Stop both service and socket; confirm they are inactive. Restore the saved boot and accepted-state `ui_dir` without disturbing other operator changes. Stage a copy of the previous binary into the active binary directory; atomic `mv` it over the candidate. Validate again with that previous binary. Start `conspect.socket` then `conspect.service`; if either fails, leave the socket and service stopped and escalate with logs.
3. Re-run the entire health gate (service/PID/hash, UI HTML and asset hashes, authenticated endpoints, increasing ticks with no new misses, advancing HLS and segment PTS/DTS). If validation or the restarted rollback's health gate fails, declare production unhealthy, preserve current state and journal evidence, and escalate; never report recovery or retry unvalidated releases. Keep every failed candidate for forensics until a separate disposal decision.

This audit tested the previous binary's version and validation and confirmed the prior UI exists. A live restart and restore is intentionally **not claimed as tested**. A maintenance-window rehearsal must prove the final step before any deployment treats rollback as fully tested.
