# ADR-0099: User-defined encoder settings per output, deduplicated into renditions

- **Status:** Proposed
- **Area:** Output / Core engine (encode)
- **Date:** 2026-11-10
- **Tracking:** [#216](https://github.com/conspect-studio/conspect/issues/216)
- **Relates to:** [ADR-0026](ADR-0026.md) (encode-once-mux-many), [ADR-0031](ADR-0031.md) (pinned FFmpeg), ADR-0035 (load-aware placement), [ADR-P006](ADR-P006.md) (fixed preview profile)

## Context

Every output today carries only a free-form `codec` hint. The pipeline resolves the encoder
from the **first** output that names one and opens one encoder for all outputs (invariant #7).
Bitrate is hard-coded at 4 Mbit/s and the GOP is fixed at one second. Profile, preset, tune,
rate control and level are not configurable, so they are whatever libav defaults to in the
linked FFmpeg version.

That last point is a correctness problem, not only a missing feature. FFmpeg 9.0 changed the
default `h264_nvenc` profile from Main to High. A controlled benchmark on the production NVENC
host (identical options, three runs each) showed 8.1.1 and 9.0.2 within noise of each other,
and High about 4% more encoder time than Main on both — so the version was not the variable,
the *unpinned default* was. Without a pin, the upgrade would have changed the production stream
silently. The FFmpeg 9.0.2 change pins the program H.264 profile to High as a stop-gap
(`multiview_ffmpeg::program_h264_options`); this ADR defines the real surface.

## Decision

1. **Encode settings are a typed, codec-agnostic model owned by the encode, not the transport.**
   Fields: `codec`, `profile`, `level`, `preset` (speed/quality), `latency` (tune class),
   `rate_control` (`cbr` | `vbr` | `cqp`), `bitrate`, `max_bitrate`, `buffer`, `gop` (a
   duration, re-stamped from the tick counter — invariant #3), `b_frames`. An output may carry
   an optional `encode` block; absent fields take the documented defaults.
2. **Defaults:** H.264 High, CBR, the current 4 Mbit/s bitrate, one-second GOP, B-frames off.
   Defaults are explicit values in our code, never libav's per-version defaults.
3. **Rendition dedup preserves invariant #7.** Outputs whose *effective* settings (after
   defaults) are identical share one encoder and one packet stream. An output with different
   settings gets its own rendition. Rendition identity is the normalised settings value, so
   ordering and omitted-vs-default spellings cannot create a spurious extra encoder.
4. **Admission accounts for renditions.** Each rendition is an encoder session with a cost in the
   placement model (ADR-0035) and against the NVENC session ceiling. A configuration that does
   not fit is refused or degraded explicitly, with a health event — never by silently merging or
   dropping a rendition.
5. **Per-family lowering, validated at load.** The model is lowered per encoder family (NVENC,
   VAAPI, QSV, VideoToolbox, libx264, software) to `AVOption` pairs in `multiview-ffmpeg`
   (`CodecOptions`, the same seam ADR-P006 uses). A value a family cannot honour fails
   validation with a precise error (the `display-kms` precedent); it is never ignored. Raw libav
   option passthrough is out of scope.
6. **Transport constraints still win.** RTP/WebRTC outputs force B-frames off; LL-HLS requires
   the GOP to align with part/segment boundaries. A conflicting user setting is a validation
   error, not a silent override.
7. **Surfaces:** config schema, API output resource (per-object authorization unchanged) and the
   Web UI expose the same model.

## Consequences

- Output streams stop depending on FFmpeg's defaults; FFmpeg upgrades can no longer change a
  profile, rate control or GOP behind our back.
- Operators get bitrate control (the hard-coded 4 Mbit/s is the largest current limitation).
- Multiple renditions cost real GPU/NVENC capacity; admission must make that visible.
- Each encoder family needs a lowering table and tests; `ffprobe` verification of the emitted
  profile/level/bitrate becomes part of the integration tests.

## Alternatives rejected

- **Per-output encoders always.** Violates invariant #7 and multiplies NVENC sessions for the
  common case of identical settings.
- **Raw `AVOption` passthrough.** Not portable across encoder families, not validatable, and it
  re-couples output behaviour to libav option names and defaults.
- **Keep inheriting libav defaults.** Shown above to change output silently across FFmpeg
  versions.
