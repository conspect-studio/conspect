# ADR-0102: Web engine — supervised headless browser host, security boundary, GPU placement, per-job resource accounting

- **Status:** Proposed
- **Area:** Input / Efficiency / Guardrails
- **Date:** 2026-11-07
- **Source:** operator request (web engine, first template windy.com); research session measurements recorded below
- **Refines:** [ADR-0083](ADR-0083.md) (URL as an input: browser contract, capture surface, supervision)
- **Relates to:** [ADR-0080](ADR-0080.md) (HTML overlay engine), [ADR-0082](ADR-0082.md) (render-to-VT), [ADR-0100](ADR-0100.md) (VT clip jobs), [ADR-0101](ADR-0101.md) (site templates), [ADR-0058](ADR-0058.md) (NV12+A), [ADR-E007](ADR-E007.md) (admission), [ADR-0017](ADR-0017.md) (GPU load policy), [ADR-0035](ADR-0035.md) (health warnings)

## Context

The product needs web pages as picture sources. The first template is an animated windy.com radar. ADR-0083 proposed a live `web_page` source and blocked implementation on a capture-surface spike; that spike has now run. ADR-0080 left remote pages and ambient credentials out of scope "until a separate security ADR". This ADR is that decision for the source side.

Measured facts that bound the answer (2026-11-07, chrome-headless-shell, whole process tree):

| Case | CPU (100% = one core) | Memory | Rate |
|---|---|---|---|
| mda001, P2000 Vulkan, embed 720p, page open | 24% | 750 MB RSS sum | n/a |
| mda001, P2000 Vulkan, embed 720p, screencast | 102% | 800 MB | 31 fps |
| mda001, P2000 Vulkan, main site 1080p, page open | 18% | 895 MB | n/a |
| mda001, P2000 Vulkan, main site 1080p, screencast | 262% | 948 MB | 48 fps |
| mda001, SwiftShader, embed 720p, page open | 358% | 690 MB | n/a |
| mda001, SwiftShader, main site 1080p, screencast | 347% | 918 MB | 0.8 fps |
| devcontainer, SwiftShader, embed 720p, one load | 99 CPU-s | 406 MB PSS | n/a |

The mda001 main-site runs were logged out, and Conspect shared the P2000. VRAM was 80–170 MB.

Other findings:

- `--disable-gpu` removes WebGL. Windy then silently shows the Wind overlay with "No data!" tiles. A wrong picture is the normal failure mode, not a crash.
- An early sampler matched one process by command line and reported 0% CPU and 100 MB. About 95% of the CPU sits in the GPU process. Accounting must use the whole process tree or a cgroup.
- `Delegate=yes` is set on mda001 (host drop-in). The repository ships no service unit. Under cgroup v2, a cgroup holding processes cannot enable controllers for child cgroups, so Conspect must move itself into a leaf first. This is not yet tested.
- `SystemMetrics` and `GpuMetrics` report whole-process figures only. `resolve_rist_secret` resolves `env:` only; there is no `op://` resolver in the binary.
- A shared-browser test (4 sources, software rendering, one run, noisy host) gave 945–1013% CPU and about 800 MB against 1859% and 1044 MB for separate browsers. Page processes stayed isolated. All sources share one GPU process, so that cost cannot be split per source. Killing the browser stopped all sources.

## Decision

**One new leaf crate, `multiview-webengine`, behind an off-by-default `web-engine` Cargo feature.** It owns browser launch, the CDP client, supervision, content validation, the resource sampler and site templates. A configuration that uses the feature in a build without it fails validation (the `display-kms` / `aes67` precedent). The default build stays LGPL-clean, GPU-free and free of native dependencies. Config types always parse.

1. **Browser contract.** Chromium-class browser, operator-supplied, discovered at runtime (`web_engine.browser_path`, then `PATH`), never bundled. Prefer `chrome-headless-shell`; a full browser with `--headless=new` also works. A minimum major version is enforced at start and reported as a capability.

2. **CDP over a pipe.** The engine launches with `--remote-debugging-pipe`, not a TCP port, so no local process can reach the debugging interface. The client is a small in-crate JSON client limited to the domains we use. Pipe mode is untested and is the first implementation task. If pipe mode fails, a credential-free page may fall back to `--remote-debugging-port=0` on `[::1]`, with the port read from stderr. A logged-in page fails closed: a local port gives any local process control of the session.

3. **`BrowserHost` interface.** All consumers obtain a page through `BrowserHost`. The first implementation is one browser per consumer. A pool (decision 11) is a second implementation, with no change to consumers.

4. **Isolation from the output.** The browser is a child process, reached only from its own threads. It publishes frames into the existing latest-slot store. The engine never awaits it (invariants #1 and #10). Frame hand-off is a single latest slot; ACK flow control runs on the browser's own thread, so a stalled consumer drops frames, never queues them.

5. **Security boundary.** A remote page is untrusted content.
   - Sandbox on: `--no-sandbox` is forbidden in production. The spike used it; running sandboxed under `conspect.service` is an early required test. If the host blocks the sandbox, the job fails with a named reason. An explicit operator override `web_engine.allow_unsandboxed = true` raises a health warning.
   - Each site gets its own profile directory, mode 0700, under the state directory, never exported in a support bundle.
   - Credentials are references only, in the existing `SourceAuth` shape: `username = { secret_ref = "..." }` and `password = { secret_ref = "..." }`. A new shared resolver provides `env:` and `op://`; today only an `env:` RIST helper exists. Conspect never logs, serializes or places the plaintext on argv. It crosses the pipe once, for login.
   - **Session at rest.** After login the session lives in the profile: the HttpOnly `_account_sid` cookie, and a user token in page `localStorage`. Any process running as the service user, and root, can recover it. Every script in that page can read the token. Profile mode, bundle exclusion and core-dump suppression (`RLIMIT_CORE=0` on the browser) reduce exposure; they do not remove it.
   - The support bundle never includes the profile or job directories. The exact key `secret_ref` is what the redactors recognise: export keeps it for reimport and the bundle removes it. A flat key such as `username_secret_ref` would be overwritten on export, so it is not used. Tests on a fill document prove both paths.
   - Navigation and requests are allowlisted per template through the `Fetch` domain. `file:` and private-address targets are blocked unless the site definition names them. This is a request filter, not an isolation boundary: it may miss service-worker, WebRTC and DNS traffic. Network isolation of the browser is the boundary to add if templates ever load untrusted hosts. Operator-authored templates stay deferred for this reason.
   - No page script receives anything from Conspect except the template's own injected code.
   - Console output, URLs and CDP traffic are redacted before logging.

6. **Content validation is mandatory.** A capture or a frame stream is accepted only after its template's validators pass (ADR-0101). A generic check also rejects a uniform frame. The process exit code is not evidence of a good picture.

7. **Rendering and GPU placement.**
   - Software rendering uses the default SwiftShader path. `--disable-gpu` is forbidden for templates that need WebGL.
   - GPU rendering uses `--use-angle=vulkan --enable-features=Vulkan --ignore-gpu-blocklist --enable-gpu-rasterization`, with `MESA_VK_DEVICE_SELECT=<vendor>:<device>` in the child environment.
   - At start the engine selects the least-used GPU from the existing load source. A GPU is usable only if it has compute utilisation below `web_engine.gpu_max_util` (default 70%) and free VRAM above `web_engine.gpu_min_free_vram_mb` (default 512 MB). The defaults are provisional until the mda001 tests finish.
   - If no GPU is usable, the browser receives none and runs on CPU. A live source then either meets its frame-rate floor or goes to `failed`. Placement is decided at start and does not move while running.
   - Device selection by PCI id cannot separate two identical cards. On such a host placement is `unpinned`, and the capability reports it. Admission then checks every matching card.

8. **Resource scopes and accounting.** Every browser, encoder and decoder process started for a job or source registers a scope `{owner, generation, kind}`, where `kind` is `cgroup(path)`, `process_tree(root)` or `pool(id)`.
   - With delegation, the move runs **first in `main`, before any thread or child exists**, so no migration race can occur: create `engine/`, write our PID to its `cgroup.procs`, confirm the service cgroup holds no process, then enable `cpu memory pids` in `cgroup.subtree_control`. Order matters: a domain controller cannot be enabled on a cgroup that holds processes. If any step fails, Conspect stays where it is, uses process-tree accounting, and raises the warning. A move changes nothing already charged, so boot-time memory stays with the parent; running this first keeps that amount small.
   - Each browser starts in `web/<owner>-<generation>/` from a `pre_exec` step that joins the cgroup before `exec`, so all its children are born inside. Reads use `cpu.stat`, `memory.current`, and `memory.peak` (never written, so it stays a lifetime peak). Teardown uses `cgroup.kill`.
   - Without delegation, Conspect walks the process tree, sums CPU time and PSS, and reaps exited children's time. The result is labelled `estimated`.
   - GPU figures join NVML per-process data on the scope's PIDs in both modes. `NvmlLoadProbe::self_share` filters to one PID today, so this needs a new multi-PID query. `nvidia-smi pmon` showed the Chrome GPU process on mda001 with 151 MB of VRAM (type C+G), but the NVML calls we would use are untested for it. A missing value reports `unknown`, never zero.
   - A 1 Hz sampler runs off the data plane and publishes a bounded `WebResourceUsage` list beside `SystemMetrics`: owner, phase, CPU, memory, peak memory, GPU utilisation, VRAM, cumulative CPU-seconds and GPU-seconds, `accounting = exact | estimated`.
   - Short-lived jobs emit a final totals record, so a job that ends between samples is still counted.

9. **Delegation support.** Both modes are supported. Delegation is detected by trying to create a child cgroup, not by reading the unit. Without it, a new `WarningCode::CgroupDelegationUnavailable` is raised only when web sources or clip jobs are configured. The text names what is lost (exact accounting, hard limits, kill-the-group cleanup) and the fix. The runbook documents the drop-in.

10. **Limits.** Each browser has CPU, memory and PID limits. With delegation the kernel enforces them. Without delegation a watchdog stops a browser over budget and records it; a fast memory spike can exceed the limit first. Defaults: `memory.max` 1.5 GiB, 200% CPU, 512 PIDs. Orphans are found and killed at start from a PID record in the state directory.

11. **Browser pools (opt-in).** Default is one browser per live source. A user may define a named pool with a source limit. Pooled sources get separate browser contexts, so logins stay apart. Pool scope figures are `exact`; per-source figures are `estimated`. A browser crash fails all members, and retry backoff applies once per pool. GPU placement is per pool. Clip jobs never join pools. Pools ship after single-browser live sources.

12. **Live sources.** A live web source uses the shared activation lifecycle (`activation` = `always_on` default | `on_demand`, states `idle` / `starting` / `ready` / `failed`, owned by `feat/rc-demand-driven-sources`). It plugs in through the agreed `start()` / `stop()` hooks and resource scope registry. `starting` phases are `browser_start`, `page_load`, `login`, `first_frame`. A source fails on start timeout, content validation failure, or a frame rate under its floor for a sustained window. Only `always_on` retries, with a per-kind backoff cap, so a bad password cannot lock an account. The capture surface is `Page.startScreencast` with JPEG; alpha views use PNG, decoded off the data plane to NV12 plus an alpha plane.

13. **Alpha is part of the engine.** Each view has `background = opaque | transparent`. A transparent view sets `Emulation.setDefaultBackgroundColorOverride` to alpha 0 and captures PNG. The screenshot path returned straight alpha and the screencast path looked premultiplied, so the engine records alpha type per capture method and converts once. A permanent reference page checks known alpha values. A transparent view fails validation if the capture has no transparency. Alpha tiles on air stay blocked until the GPU compositor accepts alpha: `reject_alpha_tiles` today sends the whole frame to the uncached CPU path. The source and player tile scalers also produce NV12 only, so an alpha path needs work there too.

## Rationale

CDP over a pipe needs no new heavy dependency, removes a listening port, and keeps the browser replaceable. A child process per consumer gives exact accounting and crash isolation; the measured shared-browser saving is real but software-only, so it stays opt-in. Validators exist because the observed failure is a plausible wrong picture.

## Alternatives considered

| Alternative | Rejected because |
| ----------- | ---------------- |
| CEF embedded (ADR-0080 default) | Large native dependency, in-process failure risk, and offscreen frames need work CDP already provides. ADR-0080 can still adopt or replace this for overlays. |
| A CDP crate (`chromiumoxide`, `headless_chrome`) | Large dependency surface for about a dozen commands; both assume a TCP endpoint or bring their own runtime. Reconsider if the in-crate client grows. |
| TCP CDP as the default | A local listener with full browser control; a page cannot reach it, but any local process can. |
| Shared browser by default | Operator chose one per source; shared GPU process breaks exact per-source accounting. |
| Fetch Windy tiles without a browser | Radar tiles are multichannel data needing Windy's shader and palette, and the access is undocumented. |
| `--single-process` | Measured worse: three times the CPU and no crash isolation. |
| Bundle a browser | Size and licence posture; ADR-0083 alternative 7 stands. |

## Consequences

- Reversible: off by default, additive config, no engine change for opaque sources.
- A live web source costs a browser for as long as it is `ready`. With `always_on` as the default, each one is a standing cost, and on CPU it can reach several cores. Admission refuses a start that does not fit, with a reason.
- GPU rendering shares a GPU with Conspect. Tests must prove the output cadence is unaffected.
- `web_engine.allow_unsandboxed` exists for hosts that block the sandbox; it is a known weakening and raises a warning.
- A site redesign breaks a template. This appears as a validation failure, not bad pictures.

## Open items

Each must pass before the matching stage ships: CDP pipe mode; sandbox under the service; logged-in GPU cost; GPU process crash recovery of the picture; the start-of-`main` cgroup move on a delegated service; NVML multi-PID attribution for the browser; output cadence soak with a browser on the same GPU.

## How this honors the invariants

- **#1, #10:** the browser is a sampled producer; no data-plane path awaits it.
- **#2:** a stalled page holds last-good and rides the tile state ladder.
- **#3:** output stamps come from the tick counter, never from page time.
- **#5, #8:** frames convert once to NV12 off the data plane, with colour tags; alpha converts once.
- **Licence:** the browser is an external process and is not linked.
