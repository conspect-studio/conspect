# ADR-0104: Switcher slice 2 — any configured source on Preview/Program, AUTO mix in the Program drive, fresh-frame take gate

- **Status:** Accepted
- **Area:** Core engine / Management / Web/API
- **Date:** 2026-11-11
- **Source:** operator request, issue #251 (closes #245, #247; #243 out of scope)
- **Refines:** [ADR-0054](ADR-0054.md) (production switcher layer), [ADR-P007](ADR-P007.md) (PVW bus), [ADR-0059](ADR-0059.md) (switcher audio)

## Context

The first slice (PR 229) runs one M/E `me1` on program `main` with one
full-canvas Program cell. On mda001 it can only CUT between the two sources
named in `[switcher]`: `validate_source_pair` in
`crates/multiview-control/src/routes/switcher.rs` answers 422 for every other
source, and `SwitcherControl::supports_auto` returns `false`.

What is true today about source decoding (read from the code and measured on
mda001 on 2026-11-11 with `GET /api/v1/sources/status`):

- Every configured source has a `TileStore` in the catalogue, and the Program
  drive is built over `catalogue_stores()`, so a rebind to any configured source
  is a pointer re-point (`CompositorDrive::rebind_cell`), never a new decoder.
- A source starts when it has a consumer (`docs/architecture/demand-driven-sources.md`).
  `activation = always_on` (the default) starts it at boot. On mda001 10 of the 12
  sources are `always_on` and `ready` with video running; `dw-news` and
  `times-square` are `on_demand` (`dw-news` ready, `times-square` failed).
- `select_preview` already takes a demand lease (`preview_lease`, video rail) on
  the selected source before enqueue, make-before-break; the Program cell is a
  `layout_cell` consumer of the demand manager (republished on every rebind by the
  drain's `publish_demand`), so whatever is on Program keeps its rails.
- The tick driver already holds a CUT for at most 50 ticks while the Preview
  source has never published (`is_primed`), then refuses it with a typed reason.

So "any source" is mostly lifting the pair rule. On-demand start already exists
through the PVW lease. Three gaps remain: `is_primed` means "ever published", so a
source that went dark long ago passes the gate and Program would show a held
(stale) or slate picture; a direct PGM punch (`select_program`) has no gate at
all; and the PVW lease is video only, so an on-demand source has no audio until
it reaches Program.

Two bugs from the first slice: #245 (the hook rebinds a cell id it got from the
program id, which the live drain overwrites with the config cell ids on its first
tick, so every tick is a rejected tick and nothing is logged) and #247 (Preview
can be set to the Program source; CUT then answers 202 and changes nothing).

## Decision

1. **Source admission (control plane).** `select_preview` and `select_program`
   accept every source of the running configuration (the accepted document's
   sources, the same list `GET /api/v1/sources` serves) that the principal may
   read (`authorize_refs`, unchanged, per object). Any other id gets 422
   "source is not in the running configuration". `select_preview` of the current
   Program source gets 422 (#247), and `cut`/`auto` while Preview equals Program
   get 422 from `/plan` and from the command route; the engine refuses the same
   cases at the tick in case the state moved between admission and the tick.
2. **Fresh-frame take gate (engine, clock thread).** A take (CUT, AUTO, PGM
   punch) applies only when the source going to Program has a *fresh* frame at
   this tick: `TileStore::state_at(tick.pts).is_live()`, the same latch-and-classify
   rule the compositor uses for the picture it draws. Otherwise the take is held
   (one slot, `pending_take`) and re-checked each fresh tick; after 50 ticks it is
   refused with "preview source has no fresh frame before the bounded take
   deadline". A second take while one is held is refused. The check is two atomic
   loads and a ring snapshot per held tick — no lock, no wait, no allocation.
   A direct PGM punch takes the same demand lease (video and audio) as a PVW
   selection before enqueue, so an on-demand source starts while the punch waits.
   An AUTO re-checks the incoming source on its terminal tick: if it is no longer
   fresh, the AUTO is aborted with a typed reason and Program keeps the outgoing
   source. The dissolve blends only a fresh incoming frame, never a held one or a
   slate. A frame rejected on any tick of an AUTO restores the buses and the
   flight bookkeeping and gives that AUTO exactly one refusal.
3. **AUTO mix inside the one Program drive.** During an AUTO flight the hook keeps
   the Program cell bound to the outgoing source and adds a second full-canvas
   cell bound to the incoming source with `opacity = elapsed / duration`
   (`CompositorDrive::set_mix_overlay`). It is the same single compositor pass with
   two tiles instead of one — no second compositor, no second canvas, no extra
   thread. Tick `start` shows only the outgoing picture, ticks `start+1 ..
   start+N-1` the dissolve, tick `start+N` completes the take (buses swap, the
   overlay cell is removed). `supports_auto()` turns true only when this hook is
   installed. Cost: one extra full-canvas tile for N ticks; on mda001 the
   previous six-cell wall drew more tiles per tick than this.
4. **Program audio follows Program.** The hook publishes the bus selection
   (Program source, plus the incoming source, start tick and duration during an
   AUTO) into a wait-free `SwapCell`, replaced only when it changes. The audio
   consumer reads it per item: on CUT it switches as today; on AUTO start it ramps
   the outgoing gain to 0 and the incoming gain to its routed level over exactly
   `SampleClock::total_at(start+N) − total_at(start)` samples (ADR-0059's
   per-sample equal-power `GainRamp`). The PVW lease takes video and audio, so
   an on-demand source has audio before it reaches Program.
5. **#245.** The Program cell id is the id of the one config cell the first slice
   admits (`config.cells[0].id`), used both for `with_cell_ids` and for the hook;
   a failed rebind is logged once per distinct error.

## Rationale

- The gate uses the compositor's own freshness rule, so "the take waited for a
  fresh frame" and "Program did not show a stale or slate picture" are the same
  fact.
- A dissolve between two full-canvas sources is exactly a two-tile composite. The
  existing `DualBusDrive` (two compositor passes plus a blend pass) was written
  for scenes with internal overlaps; it is unused in production and would triple
  the per-tick compositor work. Not needed for single-source buses.
- Starting on-demand sources stays where it is (the demand manager's worker, off
  the clock). The engine never waits for a start: it samples a store.

## Alternatives considered

| Alternative | Rejected because |
| ----------- | ---------------- |
| Keep `is_primed` as the gate | A source that published once and then died passes it; Program would show a held or slate picture. |
| Wire `DualBusDrive` into the run path for AUTO | Three compositor passes per tick during a mix and a second drive's store set to keep in sync; no benefit for one-cell buses. |
| Block the REST call until the source primes | The control plane would hold an HTTP task for seconds; the engine already owns a bounded hold with a typed refusal. |
| Start every source at boot | Already the default (`always_on`); operators choose `on_demand` on purpose. |

## Consequences

- Invariant #1: the clock never waits on a source or a take. Tests prove zero lost
  ticks when the selected source never produces a frame, during a CUT and during
  an AUTO (`crates/multiview-engine/tests/switcher_slice2.rs`).
- Invariant #10: command admission stays `try_send` into the 64-slot mailbox; the
  hold is one slot; the bus-selection tap is a latest-wins `SwapCell`.
- The first-slice tests that pinned "outside the configured pair → 422" now pin
  the new rule (a source not in the running configuration, or one the principal
  may not read, is refused).
- A source added at runtime after the run started is not in the take gate's store
  map; a take to it is refused at the deadline with the typed reason, never
  composited stale. Widening that is a follow-up.
- Out of scope: WIPE/DIP (since rendered by [ADR-0111](ADR-0111-me-dip-wipe.md)), keyers, more than one M/E, layout-as-a-source (#243).
