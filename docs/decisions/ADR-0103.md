# ADR-0103: Shared monitor wall — compose once, encode once, one MoQ stream for Preview and source tiles

- **Status:** Accepted
- **Area:** Preview / Streaming
- **Date:** 2026-11-11
- **Source:** operator report on mda001 ("1fps preview"), issue #250
- **Relates to:** the MoQ output adapter (`moq_outputs/factory.rs`), the optional preview ladder (`preview_vertical.rs`, `preview_runtime.rs`), issue #241 (MoQ per-viewer queue)

## Context

On the production desk only Program is live video. The Preview monitor and every source tile are JPEG stills (1 fps and 0.5 fps). The per-input WHEP path costs one encoder per viewer per source and is capped at 4 sessions, so it cannot carry a wall of 12 sources to several desks.

The relevant facts:

- **Frames.** Every source already has a lock-free `TileStore<Nv12Image>`. The JPEG stills read from it.
- **Publishing.** The window registry already publishes optional renditions next to production through `OptionalRegistryPublisher` and the bounded `OptionalWindowProducer`. MoQ viewers attach to any registered output by id.
- **mda001.** It has one RTX 4060 (NVENC, about 13 % encoder load) and 10 cores at about 25 %.
- **Issue #241.** The per-viewer MoQ reservation is `MAX_QUEUE_PACKETS = 512`. A 1080p Program with six AAC tracks, about 265 packets/s, already fills it. A wall stream must therefore stay far below that packet rate.

## Decision

One off-clock worker thread (`moq-wall`) composes and encodes one wall picture for all viewers. It runs only when `MULTIVIEW_MOQ_WALL=1`.

- **Composition** (`crates/multiview-cli/src/monitor_wall.rs`). The worker wakes at the production cadence divided by an integer (default 2, which gives 15000/1001 on mda001). It reads each source's newest frame with `LatestSlot::load` on that source's tile store. That read is wait-free and does not move the tile's latch watermark, so the compositor's frame selection is unchanged. It box-scales each frame into its grid cell in pure Rust: 4×4 cells of 320×180, a 1280×720 picture, sources sorted by id. A source that has no frame leaves its cell black. The Preview monitor is the cell whose source is the Preview-bus source, because every configured source already has a cell, so it needs no extra cell.
- **Encode.** One `VideoRenditionEncoder` (`h264_nvenc`; `libx264` only in a `gpl-codecs` build, per the LGPL rule) with no B-frames, a GOP of at most 1 s and about 3 Mbit/s. It is video only. PTS is the worker's frame counter, never a float rate. The encoder opens once per run factory and never per viewer.
- **Publish.** The worker claims the factory's optional publisher and registers one rendition: `output_id = "wall"`, bus `wall`, dependencies = every cell source plus the output. Each encoded frame is offered with `OptionalWindowProducer::offer_complete`, a bounded `try_send` into the registry ingress. A full queue drops the frame and fences recovery to the next keyframe. At 15 fps this is about 15 packets/s, under 3 % of the #241 cap.
- **Transport.** A new `WhepScope::Wall`. `RegistryFeedFactory::output_scope` resolves it only to the registered `wall` output on the `wall` bus and never falls back to Program. It is a single rendition, not an ABR family.
- **API.**
  - `GET /api/v1/preview/wall` returns `{generation, width, height, cadence, cells:[{source,x,y,w,h}], preview_source}`. Each read also renews the preview-demand lease of every cell source, the same lease a still poll takes.
  - `POST /api/v1/preview/wall/moq` and `DELETE /api/v1/preview/wall/moq/{lease_id}?generation=` work like the Program lease routes.
- **Authorization.** The wall shows every source's pixels, so it is a whole-system artifact. The geometry read and the lease both require an unscoped principal (`require_unscoped_for_whole_system`), and the lease also requires Write, like Program. A scoped principal gets 403 and its desk keeps the stills, which already apply per-object authorization. We do not blank cells per principal: that would need one encode per principal, which the issue forbids.
- **UI.** One `WallStream` provider on the desk opens one lease, one WebTransport session and one `VideoDecoder`. Each tile and the Preview monitor `drawImage` their crop onto their own canvas. Any failure, a missing cell, or a frame older than 2 s puts that surface back on its existing still. The original wall ladder was MoQ, then stills; the WebRTC rung is specified in the amendment below.

## Amendment: WebRTC wall fallback (2026-11-11)

The wall now has a second transport rung: MoQ, then one video-only wall WHEP focus, then per-source stills. The wall worker publishes the newest composed NV12 picture to a wait-free latest-value slot after its encode succeeds. A WHEP session samples that slot through the existing bounded, drop-oldest per-session encoder pump. It never samples the Program slot. Each WebRTC viewer adds one preview encode, bounded by `webrtc.preview_max_focus` and `preview_max_focus_per_scope`; shared WebRTC encode remains issue #228. The 13 desk surfaces share one `<video>`, whose presented frames are copied once into the store canvas before cropping. The browser releases its focus on unmount, `pagehide`, and a failed session. A failed MoQ rung stays on WebRTC until page reload; attempting MoQ again would risk repeated focus churn and a stalled desk.

The worker still needs the optional window subscription factory, so a build without `moq-output` or a run without that factory refuses wall WHEP with typed `wall-unavailable` (503), never Program pixels. A configured run opens one wall encoder while active; the existing optional registration and worker lifecycle remain off-clock. The new latest-picture publication is off-clock as well; WHEP readers take only a `SwapCell::load`, and per-session feeds have fixed capacity. A slow WHEP peer drops samples in its own feed, never blocks the wall worker or output clock. Each latest-value picture carries the wall generation. A WHEP session captures its opening generation; after a layout change, its reader refuses new-generation pixels until the browser polls new geometry and opens a fresh session. The store paints a downscaled WHEP video to the authored wall dimensions before any cell crop. The worker currently retains its optional encode even without subscribers; that existing ADR-0103 behavior is not expanded by the WHEP rung and a demand-driven encoder stop is follow-up work.

## Isolation (invariants #1 and #10)

- The worker is its own thread. It is not the output clock, not the bake consumer and not a tokio task.
- It shares only wait-free state with the clock path:
  - tile-store `LatestSlot` loads, which are lock-free and never write the watermark;
  - the `WindowSubscriptionSlot` `SwapCell` load;
  - the registry ingress `SyncSender::try_send`.
- The one lock it takes is the optional-publisher state mutex, and only at registration. That mutex is never taken by the clock or the bake consumer; the registry's `pump` reads the published snapshot through its `SwapCell`.
- Nothing waits for the worker. A wedged worker (for example a hung native encode) only stops new wall frames. Its registration remains, and viewers see a stalled stream and fall back to stills after 2 s.
- If the worker dies, including by a panic unwinding its thread, a drop guard withdraws the geometry (the route answers 503) and the registration retires.
- Chaos tests in `monitor_wall.rs` (`a_blocked_wall_worker_costs_the_output_clock_zero_ticks`, `a_panicking_wall_worker_disables_only_the_wall`) wedge or panic the worker on its first frame while a real pipeline drives 40 ticks. They assert that all 40 ticks are emitted with contiguous PTS and that no wall geometry is published.

## Rationale

- **Cost.** Composing in the off-clock worker leaves the compositor and the clock untouched. One encode means viewer count does not move the encoder count. 16 cells at 320×180 scaled on the CPU in integer arithmetic is a small fraction of one core at 15 fps, and one NVENC session at 720p15 is a small fraction of the 4060.
- **Reuse.** The worker uses the existing optional registry and MoQ attach path, so it needs no change in `output_window_registry.rs` queue logic or in `multiview-moq`, which #241 owns.

## Alternatives considered

| Alternative | Rejected because |
| ----------- | ---------------- |
| Per-input WHEP or MoQ per tile | One encode per viewer per source; capped at 4 sessions. |
| A second compositor pass on the clock thread | Puts work on the clock path, which the issue forbids, and risks invariant #1. |
| Reuse `PreviewVertical` (the Program ladder) | It scales the Program canvas and shares its audio; the wall is a different picture with no audio. Only its pattern (bounded ingress, permit, optional registration) is reused. |
| swscale per cell | It allocates a frame per call. The integer box scaler needs no FFI and was enough at 320×180. |
| Per-principal blanked walls | One encode per principal; not needed while scoped principals keep stills. |

## Consequences

- The wall takes the factory's single optional-publisher claim. It cannot run in the same process as the measured optional Program ladder (`MULTIVIEW_MOQ_PREVIEW_CONFIG_FILE`); whichever claims the publisher first wins and the other logs that it is unavailable. mda001 does not enable the ladder.
- The wall's source demand rides the geometry poll. A desk that stops polling lets idle sources close after the usual preview lease (5 s).
- The picture size is fixed per process. Sources added beyond capacity get no cell and keep their stills.
- The default build is unchanged: the module exists only with `moq-output`, and the feature stays off unless configured.
