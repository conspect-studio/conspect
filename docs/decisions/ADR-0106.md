# ADR-0106: Local audio devices (CoreAudio, WASAPI) through cpal, isolated by lock-free rings and the existing audio servo

- **Status:** Proposed
- **Area:** Resilience & A/V / Local devices
- **Date:** 2026-11-11
- **Source:** product-owner request for macOS and Windows hardware support; issue #276
- **Builds on:** [ADR-0011](ADR-0011.md) (macOS + Windows native), [ADR-0044](ADR-0044.md) §5 (display audio: FIFO + servo + adaptive resampler), ADR-R005 (audio store, gap-free reads), [ADR-0033](ADR-0033.md) (AES67: an audio-only source)
- **Design note:** [local-audio-devices.md](../architecture/local-audio-devices.md)

## Context

Conspect has no way to use a local microphone, line input or audio interface as a source, and no way
to play program audio to a local output, except ALSA HDMI on a KMS display head (ADR-0044 §5). The
macOS and Windows targets (ADR-0011) need both. FFmpeg's `avfoundation`/`dshow` input devices can
capture audio, but they deliver it on FFmpeg's demux thread with no device-clock information, and
FFmpeg has no matching output device on either platform.

A device callback runs on an OS real-time thread, and the device sample clock is a separate crystal
from the output clock. A wrong design here breaks invariant #1 (output clock never blocks) or #10
(the engine never waits on a peer), so this is class R3.

## Decision

Add an off-by-default `audio-device` feature backed by [`cpal`](https://crates.io/crates/cpal)
(Apache-2.0; CoreAudio on macOS, WASAPI on Windows) in a new leaf crate `multiview-audio-device`
(`#![forbid(unsafe_code)]`; all FFI stays inside cpal).

1. **Input source** `kind = "audio_device"` (audio-only, like AES67: no tile, no video store).
   - The cpal input callback only converts the device samples to interleaved `f32` and pushes them
     into a preallocated wait-free SPSC ring ([`rtrb`](https://crates.io/crates/rtrb), MIT OR Apache-2.0).
     No lock, no allocation, no syscall. A full ring drops the new samples and counts them.
   - The stream opens at 48 kHz (the canonical rate); a device without 48 kHz is refused with a
     latched warning.
   - A normal-priority pump thread pops the ring every few milliseconds, maps channels, and
     time-stretches with `multiview_audio::AdaptiveResampler` (same rate, ±ppm). A buffer-level
     servo (the ADR-0044 `BufferServo` shape) holds the store's unread frames (new wait-free
     `AudioStore::unread_frames()`, head minus read cursor) near a target,
     so device drift is absorbed within a clamped band. It publishes into an `AudioStore::live`
     store.
   - Stale audio is never published: after a pump stall or ring overflow the pump discards the
     ring and re-primes; above target + 100 ms unread it discards incoming frames to the target.
   - The output clock reads the `AudioStore` wait-free, as for every other source. No callback,
     a stalled device, or a lost device reads as silence (gap-free store).
2. **Output** `type = "audio_device"`.
   - The engine pushes each tick's program audio into a long-lived wait-free engine→drain SPSC ring
     (one per output, never replaced; drop on full, counted). After any engine drop or drain stall
     the drain discards the whole stale backlog and re-primes from fresh frames. No mutex is shared with the device side; the HDMI `DisplayAudioPublisher` is
     not reused because it takes a short lock.
   - A new device-paced drain loop (reusing `BufferServo`, `AdaptiveResampler`, `ChannelMatrix`)
     tops a device ring up to its target as the callback consumes it, and servos the engine→drain
     fill. The HDMI `drain_loop` is not reused: it relies on a PCM write that blocks to pace it.
   - The cpal output callback pops the device ring and fills any shortfall with silence. A callback
     heartbeat distinguishes underrun, ring full, stalled and lost.
   - Channels follow the device's own configs (not the HDMI ELD rule); the rate is 48 kHz.
3. **Device lifecycle.** One long-lived helper thread per device owns the stream. A ring is reset
   or reused only after the old stream's close is confirmed (callback quiescence); a stuck close
   keeps the old generation and starts no replacement. Requests are
   single-flight with a 2 s deadline. Late results are discarded by generation. A helper stuck in a
   device call is not replaced: the device goes to a latched `device_call_stuck` state. A cpal error
   callback or a stopped heartbeat marks the stream lost; the pump or drain reopens with capped
   backoff. The engine never waits for any of it.
4. **Configuration and API.** A device is bound by its stable cpal `DeviceId` (CoreAudio UID,
   WASAPI endpoint id), or by an exact name that must be unique, or `default` (follows the OS
   default; on macOS input by polling the default device id every 2 s, since cpal has no monitor
   for it). Optional `channels`. `multiview devices audio` lists devices and ids. Local devices are
   file-configured only: one shared admission rule rejects `audio_device` on every control-plane
   mutation and import path, so a remote client cannot open a microphone.
5. **Permissions.** macOS: TCC consent for a stably signed binary with
   `NSMicrophoneUsageDescription`. Known limit: without unsafe code the source cannot read the TCC
   status, so on macOS a denied microphone is reported as `input_silent` or `stalled` with
   permission named as a possible cause, never as `permission_denied`. Windows: the per-app privacy
   setting; an access error is `permission_denied`. All are typed, latched states, not crashes.

## Rationale

- **cpal** covers CoreAudio and WASAPI with one safe API, is widely used, and is permissively
  licensed. Writing our own CoreAudio and WASAPI bindings would add two unsafe FFI surfaces.
- **SPSC rings everywhere a clock boundary is crossed:** wait-free on both ends, fixed size, no
  allocation. A mutex at the engine boundary or the RT boundary lets a descheduled holder stall the
  other side (priority inversion), which invariant #1 forbids.
- **Reuse:** the AudioStore (gap-free, drop-oldest, wait-free read), the adaptive resampler, the
  servo and the channel matrix are tested already. The new code is the ring adapters, a
  device-paced drain, a wait-free `AudioStore::unread_frames()` for the servo, and the device
  lifecycle.

## Alternatives considered

| Alternative | Rejected because |
| ----------- | ---------------- |
| FFmpeg `avfoundation` / `dshow` audio capture | No output device on either platform. Audio arrives on the demux thread with no device-clock signal, so drift cannot be servoed. One path per platform instead of one. |
| Direct `coreaudio-sys` / `windows` crate bindings | Two new unsafe FFI surfaces to keep correct; cpal already wraps both. |
| Mutex-guarded FIFO touched by the callback | Priority inversion: a preempted lock holder stalls an RT audio thread (glitches), and any shared lock couples the device to the engine side. |
| Run the device as the master clock | Breaks invariant #1: the output clock is the only master. Devices are slaved by resampling. |

## Consequences

- New optional dependencies (cpal and its platform crates, rtrb), pinned to exact versions and
  target-specific to macOS and Windows, appear only with `audio-device`. Any NOTICE-bearing
  transitive crate is attributed in `THIRD-PARTY-NOTICES.md`. `cargo check --workspace` and the default build stay unchanged. CI adds
  `cargo deny` over the feature graph for the macOS and Windows targets.
- The feature is supported on macOS and Windows. cpal's Linux backend needs `libasound`; Linux
  device audio is not part of the first delivery.
- Tests: the ring adapters, pump and drain run in CI over a simulated device (drift, stalls,
  bursts, errors, stuck opens). A real-engine chaos test at 25, 29.97 and 60 fps proves one frame
  per tick, bounded queues and flat thread count and memory. Real-device runs happen on macOS and
  Windows test hosts.
- Invariants #1 and #10 hold by construction: the engine touches only the `AudioStore` (wait-free
  read) and the engine→drain ring (wait-free push); the RT callback touches only its ring.
